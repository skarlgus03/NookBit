# Backend safety checks

이 문서는 정리 흐름의 안전 경계와 재현 테스트를 기록한다. 화면의 모양과 무관하게 같은 경계를 유지해야 한다.

다른 볼륨 이동은 아직 지원하지 않는다. 후속 작업의 상태·복구·되돌리기 설계는 [다른 볼륨 전송 설계](cross-volume-transfer-design.md)를 따른다. 설계 문서가 있다고 기능이 활성화된 것은 아니다.

## 확인한 흐름

| 상황 | 기대하는 동작 | 재현 테스트 |
| --- | --- | --- |
| 두 번째 이동의 기록 실패·목적지 충돌 | 앞서 옮긴 파일을 안전하게 되돌리고 실패로 기록한다. 다른 파일을 덮어쓰지 않는다. | `safe_executor_tests.cpp`: `testBatchFailureRollsBackEarlierMove` |
| 앞선 파일을 옮기는 동안 뒤 파일 변경 | 해당 파일의 이동 의도를 기록한 뒤 내용 해시·파일 ID·크기·수정 시각을 다시 확인한다. 바뀐 파일은 옮기지 않으며 앞선 이동은 되돌린다. 되돌림이 불확실하면 확인 필요로 멈춘다. | 같은 테스트의 `sourceChanged` 시나리오 |
| 이동 중 앱 종료로 파일 위치가 나뉨 | 다시 연 SQLite 기록과 실제 두 위치를 비교한다. 여러 파일이 출발지·목적지에 나뉘어 있으면 자동으로 이동하거나 완료 처리하지 않는다. | `recovery_service_tests.cpp`: `testInterruptedBatchNeedsManualReview` |
| 되돌리기 원래 위치에 새 파일 존재 | 기존 파일을 덮어쓰지 않고 되돌리기를 거부한다. | `safe_executor_tests.cpp`: `testApprovedSingleFileMoveAndUndo` |
| 되돌리기 의도 기록 도중 이동된 파일 내용 변경 | 실제 되돌리기 직전에 두 위치를 확인하고 변경된 내용은 옮기지 않는다. 기록은 확인 필요가 된다. | 같은 테스트의 `changingUndoHistory` 시나리오 |
| 감시 제안 수락 | 파일 경로만 대기 등록한다. 중복은 추가하지 않으며 이전 미리보기는 무효화한다. | `preview_controller_tests.cpp`: `testWatchedFilesUseNormalSortWorkflow` |
| 감시 파일 최종 확인 실패·성공 | 실패하면 파일과 저장된 대기 목록을 유지한다. 성공하면 이동한 항목을 목록과 저장 문서에서 제거한다. 되돌리기도 일반 파일과 동일하다. | 같은 테스트 |

## 기록과 대기 목록의 차이

SQLite 기록은 이동·승인·복구 상태를 보관하고, `pending-files.json`은 사용자가 등록한 경로만 보관한다. 이동 성공 전에는 대기 항목을 제거하지 않는다. 완전한 성공을 확인할 수 없는 중단 작업은 대기 경로가 남을 수 있으며, 파일이 실제로 없다면 목록에 표시한다. 모호한 복구 결과를 근거로 대기 항목이나 파일을 임의로 삭제하지 않는다.

## 검사 범위와 한계

전송 기록 기반은 `transfer_journal_tests.cpp`에서 파일을 실제로 옮기지 않는 테스트 지문으로 검사한다. 기존 승인 계획을 바꾸지 않고 단계 이벤트와 스냅샷을 함께 저장하는지 확인한다. 이는 다른 볼륨 이동 성공 테스트가 아니다. 기존 SQLite v1에서 v2로의 이행, 실패 롤백·재시도, 향후 Schema 쓰기 거부도 같은 테스트에 포함한다.

오류 주입은 임시 파일과 SQLite에서 의도 기록·이동·완료 기록 사이의 상태를 재현한다. 실제 OS 프로세스를 강제 종료하거나 전원을 차단하는 시험은 아니다.

현재 이동은 `MoveFileExW`의 덮어쓰기 없는 같은 볼륨 이동을 사용한다. 직전 검사와 운영체제 이동 사이에도 외부 프로그램이 파일을 바꿀 아주 짧은 경쟁 구간은 남는다. 이번 보강은 배치 시작 시점 검사만으로 뒤 파일을 이동하던 구간을 줄인 것이며, 검사와 이동을 하나의 원자적 파일 핸들 작업으로 만든 것은 아니다. 이동 후 내용도 검사하고 불확실하면 복구 확인을 요청한다. 다른 볼륨으로의 복사·삭제 이동은 지원하지 않는다.
