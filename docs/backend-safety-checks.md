# Backend safety checks

2026-10-06 단계 증거 보존 회귀를 수정했다. 구형 시작 복구는 v2 상태를 변경하지 않고 경고 목록에 유지한다. 새 실행기의 오류 표시는 Planned/Skipped/RolledBack을 덮어쓰지 않는다. 실제 SQLite·임시 파일로 수정 전 실패를 재현한 뒤, 부분 복원 후 시작 검사와 충돌 해소 뒤 되돌리기 재시도(v1/v2), Qt 시작 경고 보존을 확인했다. 기존 자동 테스트 19/19과 실제 C:/D: 회귀 16개도 통과했다. 상세 계약은 [전체 작업 복구](interrupted-operation-recovery.md)의 단계 증거 보존 회귀를 참고한다.

이 문서는 정리 흐름의 안전 경계와 재현 테스트를 기록한다. 화면의 모양과 무관하게 같은 경계를 유지해야 한다.

앱의 다른 볼륨 이동·완료 작업 되돌리기와 명시적 전체 중단 복구 선택을 활성화했다. 시작은 읽기 전용 검사만 하며 확인 취소/나중에는 기록·파일을 변경하지 않는다. 선택 버튼은 실행과 공유하는 사전 검사 결과로 제한하며 확인 후 설정 변경·낡은 승인·미지원 시작·부분 역전송은 재검사에서 차단한다. 기본 테스트는 중복 확인/조회 실패도 검사한다. 자동 19/19과 실제 C:/D: 회귀 33개가 통과했다. 보존 임시 파일의 별도 승인 정리 화면과 정확한 진행률/안전 취소는 남아 있다. 상태·복구·되돌리기 설계는 [다른 볼륨 전송 설계](cross-volume-transfer-design.md)를 따른다.

## 확인한 흐름

중단된 전체 작업은 [조회·명시적 복구 계약](interrupted-operation-recovery.md)을 따른다. 2026-10-05 자동 테스트 19/19과 실제 전체 선택 처리 10개가 통과했다. 이어 개별 복구→전체 정방향 재개 11개도 통과했다. 선택 감사 실패나 충돌에는 원본·임시 파일을 보존하며, 앞부분 손상은 보호 검사에서 차단하고 나머지 이동도 시작하지 않는다. 원래 승인 내용·단계 ID·설정·규칙을 복구 도중에도 재확인한다. 부분 보존 되돌리기 6개도 통과했다. 복사 완료/삭제 없이 이미 이동한 파일만 복원하고, 임시 파일 확인 등록은 SQLite 재열기 및 이동 복원 완료 후에도 남는다. 완료된 되돌리기의 보존 부분 정리는 명시적 승인 지문·보호된 원본/임시 핸들·접두부 검사·별도 의도/완료 감사를 사용한다. 실제 두 볼륨 13개와 자동 승인 검사 8개가 통과했다. 실제 정리 강제 종료 후 마무리/새 점유 차단 및 미지원 복사 시작 전/부분 역전송의 무변경 차단 5개도 통과했다. 후자의 두 경계는 재개 지원이 아니라 보존·차단 정책이며 앱 시작/UI 연결은 별도다.

`commit_transfer_copy_tests.cpp`의 `testTransferWithMissingParents`는 실제 SQLite의 CopyIntent 저장이 폴더 생성보다 먼저임을 확인한다. 정상 복사·확정·원본 제거, 의도 저장 실패 시 생성 없음, 생성/검증 결과 저장 실패·취소 시 원본과 생성된 자료 유지, 잘못된 목적지 볼륨 거부를 검사한다. 한 볼륨에서 저수준 승인 복사 어댑터를 시험하는 계약이며 실제 두 볼륨 v2 승인 계획/앱 지원을 의미하지 않는다.

검증된 임시 복사본 정리는 `commit_transfer_copy_tests.cpp`의 `testVerifiedStagingCleanup`에서 검사한다. 정상 취소 후 명시적 정리, 원본/임시 내용 변경·동일 내용 다른 객체·최종 경로 충돌·정리 의도 저장 실패·제거 후 결과 저장 실패와 재시작 기록 마무리·부분 복사본 보존·읽기 전용 임시 파일·잘못된 서명·의도 저장 도중 최종 경로 점유·상위 NeedsRecovery 보존·삭제 후 같은 이름 새 파일 재삭제 거부를 다룬다. `testProtectedCleanupSession`은 원본과 임시 파일의 쓰기 차단, 세션 해제 시 삭제 없음, 승인 볼륨 GUID 변경 거부를 검사한다. `testReverseStagingCleanup`은 역전송 취소 정리 후 완료된 이동 결과는 그대로이고 RolledBack으로 오인하지 않는지 확인한다. 삭제 대상은 모두 테스트가 만든 임시 자료다.

`transfer_journal_tests.cpp`의 `testStagingCleanupJournal`은 정리 의도 건너뛰기·낡은 증거·승인 해시 변경 거부, 실제 SQL 감사 실패 시 전체 롤백, 의도/제거 결과 재생과 의도 이벤트 누락 시 손상 거부를 검사한다. `testCleanupMigrationAtomic`은 Schema v4의 기존 기록을 보존하며 v5로 이행하고, 실패 시 컬럼/버전 롤백 후 재시도가 가능한지 확인한다. 부분·미기록 복사본 삭제와 실제 두 드라이브 시험은 포함하지 않는다.

명시적 완료 기록 복구는 `commit_transfer_copy_tests.cpp`의 `testExplicitCompletionRecovery`에서 실제 임시 파일·SQLite로 검사한다. 제거 결과/완료 기록 실패, 복구 필요 기록까지 끊겨 남은 SourceRemoveIntent/SourceRemoved, 상위 NeedsRecovery, 새 원본 위치 점유·최종 내용 변경·같은 내용의 다른 객체·임시 위치 점유·잘못된 서명·제거 의도 없는 소실을 다룬다. 실제 SQL 완료 실패 후 기록 전체 유지와 명시적 재시도, 역전송 완료 복구, 미해결 형제가 남은 배치의 상위 상태 보존을 확인한다. `testProtectedRecoveryGuard`는 저장 동안 최종 파일의 쓰기/삭제 차단과 원본 부재 시에도 승인 볼륨 GUID 재검증을 확인한다. 파일 삭제·복사 재개·임시 정리나 실제 두 드라이브 시험은 아니다.

`transfer_journal_tests.cpp`의 `testRecoveryCompletionContract`는 낡은 시도·다른 최종 객체·승인 해시 변경 거부, 제거 의도 요구, 복구 감사 이벤트 실패의 전체 트랜잭션 롤백, 재시작 이벤트 재생과 반복 완료 거부를 검사한다. `testRecoveryMigrationCompatibility`는 Schema v3의 기존 전송 이벤트/승인 해시를 보존하며 v4로 이행하고, 이행 SQL 실패 시 컬럼/버전 전체 롤백 후 재시도가 가능한지 검사한다.

혼합 배치는 `safe_executor_tests.cpp`의 `testMixedBatch`에서 복사→이름 변경→복사 순서로 검사한다. 전체 완료와 역순 되돌리기, 뒤 의도 저장 실패/원본 변경 후 앞선 두 방식의 보상, 불확실한 복사 실패 시 자동 보상 중단, 보상 경로 충돌 시 반환 시작 전 거부, 수동 배치 되돌리기의 전체 사전 점검, 역전송 제거 실패 시 남은 두 복사본 보존과 조기 중단을 확인한다. 이미 돌아온 이름 변경 단계의 RolledBack은 부분 보상 실패 후에도 유지한다. 볼륨 구분은 논리적 대역이며 파일·SQLite는 실제 임시 자료를 사용한다. 실제 두 드라이브 혼합 배치 시험이나 앱 활성화를 의미하지 않는다.

v2 역전송 연결은 `safe_executor_tests.cpp`에서 논리적 두 볼륨 대역·실제 임시 파일·SQLite로 시험한다. 양쪽 승인 볼륨이 정확히 뒤집혀 복사/제거 포트에 전달되는지, 별도 역전송 시도·새 객체 지문·원자적 RolledBack·최초 해시 보존·반복 거부를 확인한다. 원래 위치 충돌·이동 파일 내용 변경·사전 볼륨 변경에는 정방향 완료 기록을 유지한다. 의도 도중 볼륨 변경·역복사 실패에는 이동 파일을 유지하며, 제거 실패에는 복원된 파일도 유지한다. 실제 SQLite RolledBack 이벤트 실패 트리거로 제거 후 기록 실패를 재현하고 복원된 파일과 복구 필요 증거가 남는지 확인한다. 실제 드라이브 분리/두 드라이브 왕복과 앱 활성화는 아직 남아 있다.

## 기록과 대기 목록의 차이

SQLite 기록은 이동·승인·복구 상태를 보관하고, `pending-files.json`은 사용자가 등록한 경로만 보관한다. 이동 성공 전에는 대기 항목을 제거하지 않는다. 완전한 성공을 확인할 수 없는 중단 작업은 대기 경로가 남을 수 있으며, 파일이 실제로 없다면 목록에 표시한다. 모호한 복구 결과를 근거로 대기 항목이나 파일을 임의로 삭제하지 않는다.

## 검사 범위와 한계

`commit_transfer_copy_tests.cpp`의 역전송 테스트는 실제 정방향 완료 뒤 새 역전송 시도로 원래 위치를 복원한다. 별도 전송 기록·복원된 객체 지문·단계/계획 `RolledBack`·반복 거부를 검사한다. 원래 위치의 사전/확정 직전 충돌·이동 파일의 내용 변경/같은 내용의 다른 객체는 덮어쓰기 없이 거부한다. 제거 의도/완료 기록 실패와 SQLite 되돌림 완료 이벤트 실패는 거짓 완료를 막고 복원된 복사본을 보존한다. 실제 앱 버튼이나 두 드라이브 왕복 시험은 아니다.

`commit_transfer_copy_tests.cpp`의 원본 제거 테스트는 확정된 정방향 시도의 실제 임시 원본만 제거한다. 원본/최종 파일 변경·원본 읽기 전용·기존 읽기 핸들·임시 경로에 다른 파일 존재를 거부하고, 제거 의도 저장 실패에는 원본을 유지한다. 제거 뒤 결과/완료 저장 실패는 최종 파일을 보존하고 복구 필요로 남긴다. 취소 시점·반복 제거 거부·남은 단계가 있는 배치의 전체 완료 금지도 검사한다. 실제 SQLite `events` 실패 트리거로 완료 트랜잭션의 전송/단계/계획 갱신이 함께 롤백되는지 확인한다. 실제 두 드라이브·역전송·프로세스 강제 종료 시험은 아직 아니다.

전송 기록 기반은 `transfer_journal_tests.cpp`에서 파일을 실제로 옮기지 않는 테스트 지문으로 검사한다. 기존 승인 계획을 바꾸지 않고 단계 이벤트와 스냅샷을 함께 저장하는지 확인한다. 이는 다른 볼륨 이동 성공 테스트가 아니다. 기존 SQLite v1에서 v2/v3로의 이행, 실패 롤백·재시도, 향후 Schema 쓰기 거부도 같은 테스트에 포함한다.

`plan_contract_tests.cpp`는 승인 계획 v1의 고정 바이트 호환, v2 계약의 모든 필드 서명, 실제 볼륨 GUID 기준 전략 선택, 현재 볼륨 교체/조회 불가/미지원 거부, SQLite 재시작 복원과 계약 변조·누락·소수 enum·모르는 버전 거부를 검사한다. DB v3 이행 도중 오류가 나면 부분 컬럼을 롤백하고, 재시도 후 기존 계획 바이트·해시가 유지되는지도 확인한다. 볼륨 교체는 조회 포트의 가짜 결과로 재현하며 실제 드라이브 분리 시험이 아니다. `staged_copy_tests.cpp`에서는 실제 Windows 조회로 동일 볼륨 v2 초안을 준비·재확인하고 목적지 폴더를 생성하거나 원본을 변경하지 않는지 검사한다.

`safe_executor_tests.cpp`는 실제 임시 NTFS 파일·SQLite로 v2 미리보기→고정 저장→승인→이동→되돌리기와 승인 해시 보존을 확인한다. 조회 포트 누락, 고정/승인/실행/되돌리기 전 볼륨 교체, 이동·역이동 의도 기록 도중 GUID 교체를 주입해 파일 작업 차단과 복구 필요 기록을 검사한다. 다른 GUID의 목적지를 흉내 낸 `VerifiedCopy` 계약은 기존 이름 변경 실행기로 실행되지 않고 Approved 상태에 남는지 확인한다. v1과 v2 모두 뒤 단계의 기록 실패·충돌·원본 변경 후 앞선 같은 볼륨 이동을 보상하는 테스트를 통과한다. 이 테스트 자체는 실제 볼륨 분리·다른 볼륨 왕복 시험이 아니다. 앱 조립부는 이후 실제 포트를 연결해 새 계획 v2를 사용하고, 실제 두 볼륨 컨트롤러 시험 5개도 별도로 통과했다.

같은 테스트의 단일 전송 경로는 논리적 두 볼륨 포트 대역과 실제 임시 파일 복사/제거·SQLite로 검사한다. 승인 계약이 `openApproved`로 전달되는지, 복사 완료가 중복 기록되지 않는지, 복사/제거 실패에 원본과 필요 시 최종 복사본이 보존되는지, 복사 결과를 이름 변경으로 되돌리지 않는지 확인한다. 대역은 한 실제 볼륨에서 기존 native 세션을 사용하므로 실제 두 볼륨 성공의 증거는 아니다. 별도로 실제 native 승인 API에 잘못된 목적지 GUID를 전달하여 임시 파일 생성 전 거부(`staged_copy_tests.cpp`, `safe_executor_tests.cpp`) 및 제거 전 두 파일 보존(`commit_transfer_copy_tests.cpp`)을 검사한다. 전송 포트의 기본 승인 API는 미지원 오류를 반환하며 기존 API로 자동 대체하지 않는다.

`staged_copy_tests.cpp`는 빌드 폴더 아래 자동 정리되는 임시 NTFS 파일로 Windows 복사 포트를 검사한다. 빈 파일/다중 버퍼 파일의 해시·객체 ID·수정 시각·기본 속성, 원본/임시 파일 쓰기와 원본 삭제 차단, 부모 이름 변경 차단과 세션 해제 후 잠금 해제, 잘못된 원본 해시·사전 변경·기존 쓰기 핸들·임시 파일 충돌·취소·없는 부모·ADS·하드 링크 거부를 확인한다. 볼륨 조회는 없는 자식 경로에도 폴더를 만들지 않는다. 취소된 부분 복사본은 남기고 원본이 보존되는지 확인한다. 일반 이동 기능에 연결하거나 원본 삭제를 허용하는 테스트는 아니다.

오류 주입은 임시 파일과 SQLite에서 의도 기록·이동·완료 기록 사이의 상태를 재현한다. 실제 OS 프로세스를 강제 종료하거나 전원을 차단하는 시험은 아니다.

`commit_transfer_copy_tests.cpp`는 실제 임시 파일 복사·최종 이름 확정과 SQLite 전송 저널을 연결한다. 복사 의도/생성 증거/검증 증거/확정 의도/확정 결과의 각 저장 실패에서 다음 파일 작업을 차단하고, 이름 변경 직후 API 오류·확정 후 DB 지속 실패도 원본과 최종 복사본을 유지한다. 재시작 후 `NeedsRecovery` 또는 마지막 미해결 단계가 복원되고 재시도를 막는지 확인한다. 충돌 파일 보존·확정 전 취소·중복 거부도 검사한다. 성공은 `DestinationCommitted`까지만이며 상위 이동 완료·원본 제거는 하지 않는다.

같은 테스트에서 세 위치 복구 검사도 다룬다. 복사 전·부분 복사·검증된 임시 파일·미기록 최종 확정·원본/최종 공존·최종 내용 변경·내용이 같지만 객체 ID가 다른 파일·제거 의도 없는 원본 소실·제거 의도 이후 원본 없음·다른 볼륨·접근 불가·계획 서명 불일치를 검사한다. 원본 소실은 테스트 전용 원본을 임시 폴더의 보관 위치로 옮겨 재현하며 복구 코드가 삭제하는 것은 아니다. 검사 전후 전송 이벤트 개수가 같고, 임시/최종 파일과 원본이 유지되는지 확인한다. 기존 복구 서비스는 전송 기록이 있는 계획을 두 위치 이동 실패로 자동 확정하거나 수동 정리하지 못하도록 검사한다. `staged_copy_tests.cpp`는 실제 쓰기 핸들 때문에 읽지 못하는 파일이 '없음'이 아닌 '확인 불가'가 되는지도 확인한다.

현재 이동은 `MoveFileExW`의 덮어쓰기 없는 같은 볼륨 이동을 사용한다. 직전 검사와 운영체제 이동 사이에도 외부 프로그램이 파일을 바꿀 아주 짧은 경쟁 구간은 남는다. 이번 보강은 배치 시작 시점 검사만으로 뒤 파일을 이동하던 구간을 줄인 것이며, 검사와 이동을 하나의 원자적 파일 핸들 작업으로 만든 것은 아니다. 이동 후 내용도 검사하고 불확실하면 복구 확인을 요청한다. 다른 볼륨으로의 복사·삭제 이동은 지원하지 않는다.
