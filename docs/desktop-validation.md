# 데스크톱 검증과 UI 개선

## 전체 앱과 코어 빌드 구분

`dev`와 `release` 프리셋은 Qt가 없으면 구성에 실패한다. 앱 없이 코어만 시험하려면 `cmake --preset core`, `cmake --build --preset core`, `ctest --preset core`를 사용한다. Windows CI는 Qt 6.8.3과 MSVC x64로 Release 앱, 전체 테스트, 배포 폴더의 UI 시작까지 검사한다. 다른 실제 볼륨에 쓰는 수동 테스트는 CI에 포함하지 않는다.

## 검사 데이터 격리

`nookbit --verify-ui`는 `ApplicationStorage`가 실행별 임시 폴더를 소유한다. 작업 기록 DB, 감시 설정, 기본 문서·다운로드 경로, UI 설정은 사용자 AppData와 레지스트리를 사용하지 않는다. 임시 공간 생성에 실패하면 사용자 저장소로 대체하지 않고 종료한다. 객체와 DB 연결이 해제된 뒤 임시 공간을 정리한다.

UI 검증 함수는 `src/presentation/ui_verification.cpp`에 분리했다. `--verify-ui --capture-ui <폴더>`로 검사에 성공한 파일 정리·설정·홈 화면을 라이트·다크 PNG로 남길 수 있다. 자동 검사는 offscreen 플랫폼과 소프트웨어 렌더러를 사용하며 Windows 글꼴 경로도 설정한다.

## 비동기 검사

미리보기는 공용 `BackgroundTaskRunner`와 `ThreadLocalOperations`를 사용한다. 경로·설정은 값으로 고정하며 작업 스레드에서 전용 저장소·스캐너·계획기를 만든다. 검사 중 입력 세대나 대기 경로가 바뀌면 결과를 적용하지 않는다. 화면은 `previewFinished` 이후에만 미리보기 또는 최종 확인 준비로 이동한다. 실패한 미리보기로 다음 화면을 열지 않는다.

폴더 감시는 별도 실행기로 직렬 검사하며 정리 화면 조작을 막지 않는다. 설정·규칙·대기 목록·폴더 변경은 진행 중인 결과를 무효화한다. 제안 수락은 재검사 완료를 기다리고, 취소되거나 파일 목록이 달라졌거나 파일 작업이 진행 중이면 등록하지 않는다. 같은 감시 일꾼을 동시에 호출하지 않아 안정 시간 관찰 상태도 직렬로 유지한다.

## 화면

파일 정리는 드래그 외에 파일 선택과 목적지 폴더 선택을 제공한다. 빈 목록 안내, 등록 결과와 오류 문구, 미리보기의 이동 예정·건너뜀·미분류·제외 배지는 공통 규격과 테마를 따른다. 설정은 `SettingsPage`로 분리하고 각 기능의 짧은 설명을 표시한다.

같은 볼륨 `MetadataRename`의 중단 후 재개·되돌리기 제한은 유지한다. 이 변경은 복구 안전 검사를 완화하지 않는다. 정상 완료·부분 실패 후 성공한 파일의 되돌리기는 기존 계약을 따른다.

## 로컬 검증 결과 (2026-10-16)

Windows x64, MSVC 14.51, Qt 6.8.3 환경에서 Debug 33개·Release 33개·Qt 없는 코어 9개 테스트가 통과했다. Release 패키지는 SDK 플러그인·QML 경로 지정 없이 `--verify-ui`와 화면 캡처를 완료했다. Qt를 사용할 수 없는 `dev` 구성이 오류로 종료하는 것도 확인했다. 실제 UI의 라이트·다크 파일 정리/설정 화면을 캡처해 배치를 확인했다.

GitHub Actions 워크플로는 추가했으며 원격 실행은 아직 하지 않았다. 물리적으로 분리된 두 볼륨 사이의 수동 검증과 같은 볼륨 이동의 중단 복구 확장은 이번 검증 범위에 포함하지 않는다.
