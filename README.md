# NookBit

홈의 **설정** 바로 아래 **알림**에서 등록된 알림 종류를 켜고 끌 수 있다. 현재 항목은 폴더 감시의 **정리 제안**이다. 알림 표시만 제어하며 감시·파일 작업·작업 기록은 계속 유지한다. 선택은 자동 저장된다. 확장할 때의 데이터와 수명 규칙은 [알림·Interact·행동 설계](docs/companion-behavior-design.md)에 정리했다.

제작 문서: [AI용 분류 규칙 작성 계약](docs/ai-rule-authoring-v3.md) ·
[캐릭터팩 제작 가이드](docs/user/character-pack-guide.ko.md).
앱의 규칙 편집기와 캐릭터 설정에서 각각 Markdown 파일로 바로 저장할 수 있다.
일반 규칙 조작 안내는 [분류 규칙 사용 가이드](docs/user/rules-guide.ko.md)에 별도로 보관한다.

NookBit은 사용자가 끌어놓은 파일을 규칙에 따라 정리하는 Windows 데스크톱 앱이다. 파일을 대기 목록에 넣고, 분류 결과를 미리 본 뒤, 계획을 저장·승인해야 실제 이동이 시작된다. 폴더 감시는 조건이 맞을 때 정리를 **제안**하며 자동으로 파일을 옮기지 않는다.

현재 저장소에는 동작하는 Qt/QML 앱, C++20 코어, 규칙 편집기, 안전한 이동·되돌리기와 테스트가 있다. 화면 디자인과 일부 설정 기능은 아직 발전 중이다. 팀원은 이 문서로 실행한 뒤 [설계와 확장 원칙](docs/architecture.md), [협업 안내](docs/contributing.md)를 읽고 작업하면 된다.

## 처음 실행하기 (Windows)

현재 UI는 폭 380의 작은 홈과 별도의 연결 창으로 구성한다. 홈은 **파일 관리(파일 정리 / 분류 규칙 / 작업 기록)**와 **앱(설정)**으로 메뉴를 묶는다. 공통 `HomeMenuButton`으로 테두리가 있는 블록형 메뉴를 표시한다. 아이콘은 왼쪽 32px, 글씨는 버튼 전체의 가운데에 18px 중간 굵기로 두며 그룹 제목은 16px 중간 굵기다. 양쪽 글씨 여백을 대칭으로 두어 아이콘 때문에 글씨가 밀리지 않는다.  현재 페이지 배경을 부드럽게 강조하며, 작은 창 높이에서는 메뉴가 스크롤된다. 상태 요약은 추후 구상한다. 대기 목록·경로 입력·정리하기·되돌리기는 **파일 정리** 페이지에 있다. 정리하기는 분류·검사 후 기존 최종 확인에서 이동을 승인하고, 분류 결과 보기는 실제 이동 없이 예상 결과를 연다. **설정**에는 앱 전체 다크모드와 폴더 감시·캐릭터·이름 충돌 설정 진입점을 모았다. 테마는 QSettings에 저장되고 규칙 편집기의 테마 버튼도 같은 전역 설정을 바꾼다. 기본 말풍선은 테마를 따르되 팩 PNG는 색을 바꾸지 않는다. 윈도우 제목 표시줄은 없으며 NookBit 제목을 잡아 이동하고 아래쪽 가장자리로 높이를 조절한다. 내부 −는 최소화, ×는 트레이로 숨기기다. 연결 창은 본체 오른쪽에 10 간격으로 붙고 페이지별 기본·최소 크기를 사용한다. 오른쪽·아래쪽 가장자리 또는 오른쪽 아래 모서리를 끌어 크기를 조절하면 페이지별로 QSettings에 기억하며 재실행 후에도 복원한다. 본체 높이와는 독립적이고 모니터 경계로 위치를 제한하지 않는다. 접기 ×는 연결 창만 숨긴다. 본체를 숨기면 연결 창도 숨고 복원하면 선택한 페이지가 다시 보인다. 페이지 전환은 규칙 초안을 버리지 않는다.

개발용 기존 정리 화면·기존 규칙 폼·말풍선 배치 테스트는 **Ctrl+Shift+D**로 여는 개발 도구에 모았다. 규칙 작성자가 쓰는 **규칙 테스트**는 규칙 편집기에 남긴다. 감시·기록·캐릭터 설정은 팝업 오버레이 대신 일반 페이지로 확장 창 안에 배치한다. 배경·본문·헤더의 표시 순서를 분리하고 본문을 클리핑하여 접기 버튼을 가리지 않게 한다. UI 검사는 각 페이지의 접기 버튼과 규칙 편집기의 테스트 버튼에 실제 마우스 이벤트를 보내 클릭 연결까지 확인한다. 세부 디자인은 계속 조정한다.

일반 UI의 기본 글씨와 작은 안내·경로 글씨는 14px로 표시한다. 규칙 캔버스의 노드 글씨 프리셋은 별도로 유지한다. 감시 설정의 재검사 간격·파일 수·전체 용량·경과 시간은 ± 조작뿐 아니라 숫자를 직접 입력하고 Enter 또는 포커스 이동으로 확정할 수 있다. 조건을 사용하려면 해당 체크박스를 켜야 하며 기존 숫자 범위·단위는 바뀌지 않는다. 값 변경 후 **조건 저장**을 눌러 적용한다.

파일 크기 블록의 비교 방식·단위는 드롭다운으로 선택한다. 새 블록은 MB 기본이며 KB=1,000 B, MB=1,000,000 B, GB=1,000,000,000 B다. 기존 MiB(1,048,576 B)·바이트 기준은 필요한 경우 호환 항목으로 표시하여 조용히 다른 크기로 바꾸지 않는다. 규칙 JSON은 계속 정확한 정수 바이트 값을 저장하며 불러올 때 반올림 없이 표현할 단위를 고른다. 단위를 직접 바꾸면 입력 숫자에 새 단위를 적용하므로 조건 기준도 바뀐다.

폴더 감시의 ‘파일 전체 크기’도 KB/MB/GB/MiB를 선택할 수 있다. 숫자와 단위를 함께 저장하고 기존 `total_size_mib`는 그대로 복원한다. 새 SI 단위는 `{"type":"total_size","threshold":100,"unit":"MB"}` 형태로 저장한다. 단위를 바꾸면 숫자는 유지하고 새 단위를 적용한다. 공통 숫자 입력은 키보드 입력과 오른쪽의 둥근 −/+ 버튼을 함께 제공한다.

글씨·버튼·입력칸·아이콘·여백 규격은 `UiMetrics.qml` 한곳에서 역할별로 정의한다. 글꼴은 설치된 Noto Sans KR을 우선 사용하고, 없으면 맑은 고딕·기존 기본 글꼴로 대체한다. 별도 글꼴 파일은 포함하지 않는다. 일반 부품은 `AppButton`, `AppComboBox`, `AppTextField`, `AppSpinBox`를 사용하며 입력칸 기본 높이는 40px다. 라이트·다크 테마에서 같은 규격을 유지한다. 새 화면에 글씨 크기·여백을 직접 적거나 공통 입력 부품을 우회하면 자동 검사가 실패한다. 범위와 사용법은 [공통 UI 규격](docs/ui-metrics.md)을 참고한다.

파일 정리 페이지는 상단 안내뿐 아니라 목록·버튼 주변을 포함한 본문 전체에서 파일을 끌어놓을 수 있다. 외부 드롭에는 복사 응답으로 목록 등록만 수행하며 원본을 옮기지 않는다. 대기 목록은 일반 이미지의 작은 썸네일을 비동기로 표시하고, 그 밖의 파일이나 읽을 수 없는·너무 큰 이미지는 Windows 파일 형식 아이콘으로 표시한다. 썸네일은 별도 파일로 저장하지 않는다. 드래그 중에는 본문을 옅은 흰색으로 덮고 목록 등록 안내를 표시한다. 큰 **결과 미리보기 / 정리하기** 버튼을 나란히 두며 **되돌리기**는 그 아래에 있다. 결과 미리보기는 독립 페이지가 아니라 같은 파일 정리 창 안의 임시 화면이다. 입력 화면이 왼쪽으로 나가고 미리보기가 오른쪽에서 들어오는 180ms 슬라이드 전환을 사용하며 돌아갈 때는 반대로 움직인다. 창 크기는 바뀌지 않고 공통 **뒤로 화살표** 또는 **Esc**로 닫으면 대기 목록·경로 입력·스크롤 상태가 유지된다. 미리보기 안에서도 정리 준비·최종 확인으로 이어갈 수 있다. 이 페이지에서 시작한 수동 정리는 **최종 확인 → 진행 → 완료/실패 결과**로 같은 서브창 안에서 슬라이드 전환한다. 최종 확인은 가운데 고정된 이동 경로를 나열하고, 확인하고 이동을 눌러야 기존 재검사·승인·실행을 시작한다. 취소·뒤로·Esc는 준비 직전 입력/미리보기로 복귀한다. 취소/확인하고 이동과 결과 미리보기/정리하기는 공통 큰 버튼 컴포넌트로 같은 높이·여백·글씨 규격과 균등 너비를 사용한다. 검사·되돌리기 로딩 표시는 메인이 아니라 서브창 위에 표시하고, 작업 중에는 업무 조작만 잠가 제목을 통한 창 이동은 유지한다. 진행 정보는 가운데에 모아 실제 파일명·처리 단계·진행률을 표시한다. 백그라운드 작업 알림만으로 페이지를 바꾸거나 창을 열지는 않는다. 상단 끌어놓기 안내와 페이지 바깥 프레임은 제거했고, 뒤로 버튼은 설명 툴팁이 있는 공통 화살표 아이콘을 사용한다. 폴더·중복 파일에 대한 기존 등록 제한은 유지한다.

필요한 것:

- Visual Studio 2022의 **Desktop development with C++** (MSVC x64)
- CMake 3.24 이상, Ninja
- **MSVC 2022 x64용** Qt 6.5 이상: Core, Gui, Widgets, Qml, Quick, QuickControls2, QuickDialogs2, Sql (Qt Quick 앱과 네이티브 트레이 빌드용)

Qt의 컴파일러 종류와 Visual Studio 컴파일러가 같아야 한다. 아래 경로는 설치 예시이므로 자신의 Qt 설치 경로로 바꾼다. Visual Studio Developer PowerShell 또는 x64 개발자 명령 환경에서 저장소 루트로 이동해 실행한다.

```powershell
cmake --preset dev -DCMAKE_PREFIX_PATH="C:/Qt/6.11.2/msvc2022_64"
cmake --build --preset dev
ctest --preset dev
.\out\build\dev\src\nookbit.exe
```

`dev` 프리셋은 Debug 빌드·테스트를 `out/build/dev`에 만든다. Qt를 찾지 못하면 C++ 코어만 빌드되고 `nookbit.exe`는 생성되지 않는다. 그때는 CMake 구성 메시지와 `CMAKE_PREFIX_PATH`를 확인한다. 실행 시 Qt DLL이 없다는 오류가 나면 먼저 위 명령으로 **재빌드**한다. Windows에서는 빌드 후 `windeployqt`가 발견되면 실행 파일 옆에 Qt 런타임과 QML 모듈을 배치한다. 발견되지 않으면 Qt 설치의 `bin` 디렉터리를 PATH에 추가하거나 `windeployqt`를 실행해야 한다.

Qt Creator에서는 저장소 루트의 `CMakeLists.txt`를 열고 MSVC x64 Qt Kit를 선택한 뒤 `nookbit`을 빌드·실행할 수 있다. Visual Studio에서도 **폴더 열기**로 CMake 프로젝트를 열 수 있으며, 같은 Qt 경로를 CMake 구성에 지정해야 한다. 일반적인 `.sln` 프로젝트가 아니라 CMake 프로젝트다.

### Release 빌드와 실행 폴더

배포 시 사용하지 않는 화면 스타일·QML 개발 도구·SQLite 외 DB 드라이버를 제외한다. 캐릭터 표시용 Qt Quick·이미지 로더와 그래픽 호환 부품은 유지한다. 제외 목록과 전체 구성 복원 방법은 [Windows 배포 구성](docs/windows-package.md)을 참고한다.

같은 x64 개발자 터미널에서 배포용 최적화 빌드와 테스트를 실행한다.

```powershell
cmake --preset release -DCMAKE_PREFIX_PATH="C:/Qt/6.11.2/msvc2022_64"
cmake --build --preset release
ctest --preset release
cmake --build --preset package-release
```

Release 빌드·테스트는 `out/build/release`에, 실행 파일과 Qt 런타임은 `out/package/NookBit-Release`에 모인다. `out/package/NookBit-Release/nookbit.exe`를 더블클릭하면 실행된다. 폴더 전체가 필요하므로 exe만 옮기지 않는다. 패키지에는 테스트 실행 파일, 정적 라이브러리, 컴파일 중간 파일을 포함하지 않는다. Windows 패키징에는 Qt의 `windeployqt`가 필요하다.

Debug와 Release는 같은 사용자 설정·규칙·기록을 읽는다. 비교 테스트는 한 앱씩 실행한다. Release에는 개발용 고정 목적지 경로를 지정하지 않으며 저장된 정리 위치를 사용한다. 이 실행 폴더는 로컬 테스트용 구성으로, 외부 배포 전 라이선스 고지·설치 방식은 별도로 준비한다.

## 앱에서 해볼 수 있는 흐름

정리 준비 검사·되돌리기의 진행 표시는 서브창 본문을 반투명 흰색으로 덮고 가운데에 표시한다. 창 제목을 잡아 이동하는 기능은 유지한다. **중단 작업 확인**도 서브창의 페이지이며 실행 확인은 같은 서브창에서 받는다.

중단 작업 목록을 불러올 때는 해당 페이지를 먼저 열고 작은 ‘목록 확인 중…’ 표시만 보여준다. 이 읽기 전용 검사에는 흰색 오버레이를 띄우지 않으며, 실제 재개·되돌리기는 기존 진행 표시를 사용한다.

**작업 기록**은 마지막 작업 시각의 현지 날짜에 따라 **오늘 / 어제 / 이번 주 / 지난주 / 이전 기록**으로 묶는다. 주 구분은 월요일 기준이며 새로고침 시 다시 계산한다. 기록 선택·파일별 경로 확인·되돌리기는 기존대로 사용할 수 있다.

왼쪽 메뉴의 **파일 정리**에는 대기 목록·미리보기·정리 동작을 모았다. **분류 규칙**은 편집 페이지로 이동하고, **폴더 감시**와 **작업 기록**은 별도 창을 연다. 감시 제안이 생기면 메뉴에 **새 정리 제안 확인**이 나타나며, 수락하면 파일 정리 화면으로 돌아온다. 작은 창에서는 정리 화면을 세로로 스크롤할 수 있다.

1. 파일을 대기 목록으로 끌어놓는다. 이 시점에는 원본 파일이 그대로 있다.
2. 규칙 편집 페이지에서 노드를 구성하거나 v3 JSON을 불러온다. 실제 파일 하나 또는 가상 파일 정보로 규칙을 시험할 수 있다. 시험은 파일을 이동하지 않는다.
3. 편집을 적용하려면 **전체 저장**을 누른다. 기본 정리 페이지의 **현재 적용 중인 규칙** 표시는 저장본을 가리킨다. **JSON 내보내기**는 현재 그래프를 별도 파일로 저장할 뿐 활성 규칙을 바꾸지 않는다. 불러온 내용도 저장 전까지는 편집 중인 초안이다.
4. 같은 이름의 파일에 대한 공통 처리를 **이름 변경·건너뛰기·작업 중단** 중 고르고 미리보기를 만든다. 선택은 사용자 설정에 기억된다. 규칙에서 별도 정책을 지정했다면 그 정책이 우선한다. 파일마다 이동 예정·목적지 충돌로 건너뜀·미분류·명시적 제외와 그 이유를 확인할 수 있다. 이후 **정리하기 → 최종 확인창에서 확인하고 이동** 순서로 진행한다. 계획 고정·저장과 검사는 내부에서 처리하며, 확인창에는 고정된 실제 이동 경로를 표시한다. 취소하면 파일은 그대로 둔다. 확인 전후 파일·규칙·설정·대기 목록이 바뀌면 이동을 막고 새 미리보기를 요구한다.
5. 이동한 파일은 마지막 이동 되돌리기 또는 작업 기록에서 되돌릴 수 있다. 모호한 중단 상태는 복구 화면에서 확인한다.

폴더 감시는 앱이 켜져 있을 때 지정 폴더를 검사한다. 이미 대기 목록에 등록한 경로는 제안 후보와 파일 개수·총 용량·경과 시간 계산에서 제외한다. 제안을 수락하면 후보가 대기 목록에 **등록만** 된다. 이후에도 위의 미리보기·승인 과정이 필요하다. 테스트할 때는 복사해 둔 임시 파일과 임시 목적지를 사용한다.

감시 후보는 처음 발견한 뒤 크기·수정 시각·파일 식별자가 30초 이상 그대로이고 재검사에서도 같은 경우에만 제안 조건에 포함한다. 변경되면 대기 시간을 다시 시작하며, 기다리는 후보가 있을 때만 추가 재검사를 예약한다. `.crdownload`, `.partial`, `.part`, `.download` 파일은 설정한 제외 패턴과 별개로 후보에서 제외한다. 앱 재시작이나 감시 폴더 변경 시에는 새로 관찰한다. 제안 수락 직전에도 재검사한다. 이 메타데이터 관찰은 다운로드 프로그램의 완료 신호가 아니므로 일시 정지가 긴 전송까지 확정적으로 구분하지는 않는다. 직접 드롭하는 대기 등록과 파일 이동 검사는 기존 흐름을 사용한다.

정리 제안의 **30분 뒤 다시 알림**을 누르면 해당 감시 폴더의 제안을 30분 동안 쉬며, 새 파일·규칙·대기 목록 변경으로도 즉시 다시 제안하지 않는다. 대기 종료 시 감시가 켜져 있으면 현재 파일과 조건으로 재검사한다. 대기 종료 시각은 사용자 설정에 저장해 같은 폴더에서는 앱 재시작 후에도 남은 시간을 유지한다. 자동 감시를 끄거나 감시 폴더를 바꾸면 대기를 해제한다. 제안 대기 중에는 폴더 스캔을 생략한다.

## 프로젝트 지도

개별 PNG·격자/직사각형 아틀라스·공통 pivot·개인 배율 분리 규칙은 [ImagePack v1](docs/imagepack-v1.md)에 정의했다. [JSON Schema](schemas/imagepack.schema.json)와 두 방식의 예제를 제공한다. 로더는 이미지 헤더·실제 크기·프레임 범위·참조를 검증하고 기본 pivot·배율을 적용한 공통 프레임 데이터를 반환한다. 기본 테스트 캐릭터는 실행 파일 옆 `imagepacks/test/`의 실제 팩을 로딩해 프레임별 pivot·시간·개인 배율로 재생한다. 기존 `character.presentation.json` 사용자 격자 프로필도 유지한다.

홈의 **설정 → 캐릭터 설정**에서 팩 폴더 가져오기·캐릭터 선택·표시 크기(10~200%)를 조정한다. 폴더에는 `imagepack.json`과 참조된 PNG가 있어야 한다. 가져오기는 화면을 막지 않고 원본을 보존하며, 검증 성공한 복사본만 `%APPDATA%/NookBitProject/NookBit/imagepacks/<UUID>/`에 보관한다. 재가져오기도 기존 팩을 덮어쓰지 않는다. 선택과 팩별 개인 배율은 QSettings에 자동 저장되어 재실행 시 복원된다. 실제 테스트용 완성 팩은 `resources/imagepacks/test/`이며, `examples/`의 JSON들은 이미지가 없는 문서 예제다.

캐릭터는 제목 표시줄·배경 없는 별도 창으로 표시한다. 왼쪽 드래그로 이동, 우클릭으로 설정, 작은 ×로 캐릭터만 숨긴다. 설정의 **캐릭터를 앱 밖에 표시**로 다시 꺼내고 **캐릭터 위치 되돌리기**로 기본 화면에 가져온다. 위치·표시 여부는 자동 저장한다. 메인 창 최소화·닫기 후에도 캐릭터와 폴더 감시는 남는다. 모니터가 제거되면 남은 화면으로 피벗 위치를 보정한다. 현재는 항상 위에 표시하며, 투명 영역 클릭 통과·탐색기 창 인식은 아직 지원하지 않는다. 아주 큰 포즈는 독립 창의 표시 영역 제한으로 잘릴 수 있다.

작업 표시줄 알림 영역의 **NookBit 아이콘**을 클릭하면 숨긴 앱을 다시 연다. 우클릭 메뉴에는 **NookBit 열기**, **캐릭터 표시**, **완전 종료**가 있다. 완전 종료는 폴더 감시와 캐릭터도 끝내며 파일 작업·팩 가져오기 중에는 비활성화된다. 저장하지 않은 규칙 초안은 창을 숨기는 동안 유지되지만 완전 종료 전에 저장해야 한다. 트레이를 사용할 수 없는 환경에서는 닫기가 기존 종료 동작으로 돌아가고, 실행 중 트레이가 사라지면 메인 창을 복원한다. 윈도우 시작 시 자동 실행은 아직 설정하지 않는다.

ImagePack의 선택적 `bubble` 설정으로 캐릭터 부착점(`attachment`)과 말풍선 자체의 정규화 피벗(`pivot`, 0~1)을 각각 지정한다. 설정을 생략하거나 `skin.kind: "default"`이면 앱 기본 말풍선을 쓴다. `image`는 팩 내부 PNG와 논리 크기·글/버튼 영역을 지정하는 방식이다. 기본 부착점은 캐릭터 피벗에서 `(0, -120)` 논리 단위이며 개인 배율을 적용한다. 방향 전환 시 말풍선 그림과 자체 피벗을 함께 뒤집되 글은 똑바로 유지한다. 화면 가장자리에서는 말풍선 전체가 보이는 배치를 우선하므로 부착점과 정확히 겹치지 않을 수 있다. 별도 창이므로 문장 길이가 달라져도 캐릭터 위치가 밀리지 않는다. 정리 제안의 **확인**은 제안 창을 열 뿐 파일을 바로 이동하지 않는다. **개발 도구(Ctrl+Shift+D) → 말풍선 배치 테스트**에서 실제 감시 상태를 바꾸지 않고 시험할 수 있다. 자세한 작성 방법은 [ImagePack 규격](docs/imagepack-v1.md#speech-bubble-configuration)에 있다.

캐릭터 상황별 문구와 스프라이트 시트 규격은 [캐릭터 표현 규격](docs/character-presentation.md)에 정의했다. `cueId`를 공통 창구로 전달하면 JSON 설정에서 문구와 애니메이션 이름을 선택한다. 사용자 앱 데이터 폴더의 `character.presentation.json`으로 기본 설정을 교체할 수 있다. 현재는 프레임 번호가 보이는 임시 테스트 시트로 실제 격자 재생·반복·상태 전환을 확인할 수 있다. 창을 숨기거나 최소화하면 프레임 타이머를 멈춘다. 최종 캐릭터 그림과 탐색기 연동은 아직 없다.

캐릭터는 현재 왼쪽 메뉴의 테스트 스프라이트로 상태 연결과 재생을 확인할 수 있다. Qt·파일 관리와 독립된 `ICharacterChannel`이 공통 상태 입력 창구이며, `CharacterController`는 그 수신 구현이다. 기능 연결부는 `CharacterUpdate`의 `sourceId`, `entryId`, 종류(`Activity` / `Attention`), `active`, UTF-8 안내 문구와 `cueId`를 전달한다. 같은 식별자·종류는 갱신하고 `active=false`로 해당 항목만 해제한다. 다른 기능의 활동·주의 요청은 유지한다. 작업 중이 가장 우선이고, 끝나면 남은 주의 요청에 따라 말 걸기 또는 휴식으로 돌아간다. 같은 종류의 여러 항목은 현재 식별자 정렬 순서의 첫 항목을 표시하며 별도 우선순위·대기열은 제공하지 않는다.

앱 조립부에서 파일 작업과 감시 제안을 공통 입력으로 변환하며, 캐릭터 수신 구현은 파일 정리 컨트롤러나 개별 작업을 호출하지 않는다. 현재 Qt 수신 구현의 `publish`는 화면 스레드에서 호출해야 하며 다른 스레드 입력은 상태 변경 없이 오류를 반환한다. 백그라운드 작업의 상태는 화면 스레드로 전달된 알림을 연결한다. 정리 준비·시작 복구 검사처럼 읽기 전용 작업에서는 작업 상태로 바뀌지 않는다. 최종 캐릭터 그림·애니메이션은 PNG 시트와 표현 JSON으로 교체하며 탐색기 창 연동은 아직 구현하지 않았다. 이번 창구는 상태 입력만 다루며 사용자 행동 전달이나 작업 실행 기능은 추가하지 않았다.

| 위치 | 역할 |
| --- | --- |
| `include/nookbit/domain/` | 파일·규칙·계획 등 핵심 자료형과 안전 불변조건 |
| `include/nookbit/application/`, `src/application/` | 포트(계약)와 유스케이스(큰 작업의 조율) |
| `src/modules/` | 규칙 판단, 이동 계획, 감시 조건 평가 |
| `src/infrastructure/` | 파일시스템, 안전 실행, JSON, SQLite 등의 구체 구현 |
| `src/presentation/` | Qt 컨트롤러와 QML 화면, 앱 시작 시 객체 연결 |
| `schemas/`, `resources/` | JSON Schema, 기본 규칙, 앱 내장 리소스 |
| `tests/` | 코어·규칙·컨트롤러·이동 안전성·QML 시작 검사 |

화면과 코어의 역할, 현재 코드에서 원칙이 아직 완전히 적용되지 않은 지점까지 [설계 문서](docs/architecture.md)에 적었다. 기능을 붙일 때는 이를 참고하되 현재 구조를 이상화해서 가정하지 말자.

## 데이터와 규칙

백그라운드 작업 패널은 [현재 단계·파일 순서·복사 바이트 진행률](docs/operation-progress.md)을 표시한다. 복사 퍼센트는 현재 파일의 복사량만 뜻하고, 검증·확정·삭제·기록이 끝나야 전체 작업이 완료된다. 정확한 비율을 알 수 없는 단계와 같은 볼륨 이동에는 임의의 퍼센트를 붙이지 않는다. 진행 이벤트는 Qt 없는 값이며 화면 스레드에서 표시만 한다.

새 다른 볼륨 작업은 [다운로드 표식 보존](docs/download-marker-copy.md)을 지원한다. `Zone.Identifier`를 원본에서 지우지 않고 복사·최종 확정·원본 제거·정상 되돌리기 때 보존한다. 원본 삭제 전 최종 파일·표식 검증 증거를 DB에 저장해 삭제 후 중단도 명시적으로 완료 복구할 수 있다. 증거 없는 옛 기록·변경된 파일/표식은 보존·차단한다. 중단 조회는 백그라운드이며 사용자 선택 없이 이동하지 않는다. Windows OS SHA-256·스트리밍 해시·보호 세션 내 검증 재사용을 적용했다. 중단 역전송·표식 임시 파일 정리는 후속이다.

정리 준비·이동 시간을 자동 표시하고 [단계별 시간 진단 로그](docs/operation-timing.md)를 앱 데이터의 `diagnostics` 폴더에 남긴다. 복사·flush·복사본 검증·목적지 확정·원본 제거 시간을 구분하며 최신 준비/이동 기록만 보관한다. 파일 내용·이름·경로는 기록하지 않고 로그 저장 실패가 이동 결과를 바꾸지 않는다.

미시작 VerifiedCopy 전용 계획은 복사 일꾼이 임시 파일 생성 전 승인 원본을 보호·전체 검증한다고 명시한 경우, 실행기의 중복 전체 검사 3회를 해당 보호 세션으로 넘긴다. 승인 검사·복사본 검증·삭제 전 재검증은 유지하며 혼합 작업·복구·보장이 없는 구현은 기존 검사를 유지한다. [적용 범위와 검증 경계](docs/download-marker-copy.md)를 참고한다.

새 같은 볼륨 전용 작업은 [빠른 메타데이터 이동](docs/same-volume-fast-move.md)을 사용한다. 파일 전체 해시 없이 보호한 객체의 이동을 시도하고, 확실한 실패는 이유를 기록한 채 다음 파일을 처리한다. 기존 승인·혼합 작업은 종전 방식이다. 새 빠른 방식의 불확실한 중단 복구는 아직 차단하며, 정상 완료/부분 실패 뒤 성공 부분 되돌리기는 지원한다.

중단 작업의 [전체 조회·명시적 복구 백엔드](docs/interrupted-operation-recovery.md)를 제공한다. 조회는 파일이나 기록을 변경하지 않는다. 사용자 선택 후 새 검사와 원자적 감사 저장을 거쳐, 정방향은 지원하는 부분 복사·확정/제거 기록 누락을 먼저 복구하고 Pending만 처리한다. 되돌리기는 이동된 파일만 역순 복원하며, 온전한 원본과 소유한 부분 임시 파일은 그대로 보존·등록한다. 이동 복원 완료 후에도 임시 파일 확인 목록은 유지한다. 실제 개별 복구→전체 재개 11개, 부분 보존 되돌리기 6개와 자동 테스트 19/19이 통과했다. 2026-10-06 실제 혼합 작업 강제 종료·새 프로세스 재개/되돌리기 7개도 통과했다. 보존 부분 파일 정리는 별도 조회 지문·명시적 승인·보호된 원본/임시 객체·접두부 재검사·의도/완료 감사로 제공하며 실제 두 볼륨 13개가 통과했다. 원본/이동 기록은 유지하고 완료된 정리만 확인 목록에서 제외한다. 실제 정리 강제 종료와 새 점유 보존, 미지원 복사 시작 전/부분 역전송의 무변경 차단 5개도 통과했다. 복사 시작 전/부분 역전송의 전체 복구 실행은 지원하지 않고 보존·차단한다. 앱 시작의 읽기 전용 안내와 명시적 전체 재개/되돌리기 선택은 연결했다. 보존 부분 파일의 별도 승인 정리 화면·캐릭터·정확한 진행률/안전 취소 UI는 남아 있다.

앱은 운영체제가 지정한 사용자 앱 데이터 위치(`QStandardPaths::AppDataLocation`)에 활성 규칙 `rules.json`, 그래프 배치 `rule-graph-layout.json`, 감시 설정 `watch.json`, 작업 기록 `history.sqlite`, 대기 목록 `pending-files.json`을 저장한다. 첫 실행에 활성 규칙이 없으면 내장된 [기본 v3 규칙](resources/rules/default.v3.json)을 복사한다. 정리 목적지는 처음에는 사용자의 문서 폴더 아래 `NookBit Organized`이며, 이후에는 **마지막으로 미리보기에 성공한 목적지**를 이 PC의 사용자 설정에 기억해 다음 실행 때 채운다. 대기 목록은 등록·제외·이동 완료 때 자동 저장하고 앱 재시작 때 경로만 복원한다. 이전 미리보기나 이동 승인은 복원하지 않는다.

복원된 경로에 파일이 없거나 폴더로 바뀌었다면 **파일 없음**으로 표시하며, 해당 항목을 빼거나 파일을 원래 위치에 돌려놓은 뒤 새 미리보기를 만든다. 저장 실패는 화면에 별도로 표시한다. 목록 문서가 손상되었거나 지원하지 않는 버전이면 원본을 덮어쓰지 않고 그 실행에서는 목록 자동 저장을 중지한다. 이 경우 앱을 닫고 앱 데이터의 `pending-files.json`을 다른 이름으로 백업한 뒤 다시 시작하면 빈 목록부터 저장할 수 있다. 이 파일에는 경로만 있고 파일 내용·이동 계획·승인은 없다.

SQLite는 기존 계획·승인 해시를 보존하며 Schema v9로 자동 이행한다. DB v2~v8의 전송·복구·임시 정리·이어쓰기·확정 감사에 더해, DB v9는 원본 삭제 전 최종 파일·다운로드 표식 검증 영수증을 추가한다. 옛 기록에 증거를 만들어 넣지 않는다. 규칙 JSON v3와 승인 계획 형식 v2는 변경하지 않는다. 새 계획 v2는 미리보기·저장·승인·혼합 이동·되돌리기·확실한 실패 시 역순 보상에 연결했다. 기존 정리·마지막 이동 되돌리기·기록 화면 되돌리기도 다른 볼륨 이동을 사용하며 구형 v1 기록은 유지한다. DB 이행 후 구형 실행 파일로 되돌리면 지원 버전 오류가 발생한다. 자세한 범위는 [전송 설계](docs/cross-volume-transfer-design.md)를 참고한다.

Windows 전송 백엔드는 임시 복사·내용/기본 메타데이터 검증·덮어쓰기 없는 최종 이름 확정과 단계 기록을 수행한다. 별도 원본 제거 유스케이스는 확정된 정방향/역방향 시도를 재검증하고 제거 의도 저장 뒤 보호된 전송 원본을 제거하며 전송·단계·계획 완료를 원자적으로 기록한다. 2026-10-04 실제 C:/D: NTFS 볼륨에서 이동·되돌리기·양방향 충돌 방지·부분 복사 재개·확정/제거 결과 기록 복구 6개 시나리오가 통과했다. 이어 테스트 작업 프로세스를 복사 중·최종 이름 확정 직후·원본 제거 직후·완료 기록 직전에 실제 강제 종료한 4개 시험도 통과했다. 각각 별도 새 프로세스에서 복구하고 되돌리기까지 검증했다. 2026-10-05에는 규칙 미리보기·승인부터 기존 실행기로 실제 같은 볼륨/다른 볼륨 혼합 이동·되돌리기·확실한 충돌 시 역순 보상을 수행한 5개 시험도 통과했다. [실행 결과와 재실행 방법](docs/cross-volume-test-run.md)을 참고한다. 2026-10-06 앱 정리/완료 작업 되돌리기 흐름을 연결하고 실제 Qt 컨트롤러 경로의 C:/D: 시험 5개도 통과했다. 로컬 NTFS의 지원하는 일반 파일만 처리하며 모든 사고 상황을 보장하지 않는다. 파일 이동·되돌리기·전체 중단 복구는 백그라운드 실행으로 연결했다. 정리 전 고정·검사와 확인 후 승인도 백그라운드이며, 미리보기·시작 복구 조회는 아직 동기이고 정확한 진행률·취소 UI는 후속이다.

승인된 전송 복사 세션은 복사 의도를 저장하고 원본을 검증한 뒤 없는 목적지 폴더를 안전하게 만든다. 조상별 승인 볼륨·일반 디렉터리 검사와 보호 핸들로 링크 우회·경로 교체를 거부하며 기존 파일을 덮어쓰지 않는다. 계획 준비/볼륨 조회는 폴더를 생성하지 않고, 실패로 생긴 빈 폴더도 임의로 삭제하지 않는다. 규칙 JSON·승인 계획·DB 형식은 이번 변경으로 바뀌지 않는다.

역전송 백엔드는 완료된 이동 결과의 파일 ID·내용을 확인하고, 원래 위치가 비어 있을 때만 같은 안전 절차로 복원한다. 별도 역전송 기록과 복원된 새 파일 지문을 보관하며 기존 파일을 덮어쓰거나 Rename 정책으로 회피하지 않는다. 실제 앱의 마지막 이동/기록 되돌리기 버튼에도 연결했다.

명시적 전송 복구 백엔드는 제거 의도가 실제 기록된 시도에서 원본·임시 파일이 없고 최종 객체·내용·볼륨이 일치할 때만 완료 기록을 복구한다. 파일을 생성·이동·삭제하지 않으며 보호된 최종 파일 핸들을 완료 저장까지 유지한다. 정방향/역방향 결과와 복구 감사 이벤트를 원자적으로 저장하며 다른 단계가 미해결이면 배치 전체를 완료로 바꾸지 않는다.

임시 정리 백엔드는 중단된 시도의 검증된 임시 객체 ID·해시·수정 시각과 온전한 원본, 최종 경로 부재를 확인한 뒤 삭제 의도를 먼저 저장하고 해당 임시 파일만 핸들로 제거한다. 정리 결과 기록이 끊기면 재시작 후 재검사해 기록만 마무리할 수 있다. 같은 이름 새 파일·변경 파일·부분 복사본·미기록 파일은 삭제하지 않으며 이동 실패/취소 상태와 승인은 유지한다. 자동 정리·복구 화면 연결은 아직 없다. 확정 의도가 기록된 임시 파일은 이 정리 기능으로 삭제하지 않는다.

최종 복사본이 기록됐지만 원본이 남은 전송은 명시적 마무리 백엔드로 처리할 수 있다. 서명·승인·두 객체와 내용을 다시 확인하고, 보호 세션에서 별도 복구 제거 의도를 저장한 뒤 원본만 제거한다. 제거/기록 실패 후 재시도도 가능하며 이미 제거된 원본을 다시 지우지 않는다. 확정 결과 미기록·부분 복사본은 이 기능으로 처리하지 않고 보존한다. 전체 중단 작업의 명시적 재개 선택 안에서 조율한다. 개별 전송 전용 버튼은 제공하지 않는다. 실제 두 볼륨에서 확인한 마무리 범위는 위 시험 결과 문서를 따른다.

부분 복사 재개 백엔드는 기록된 임시 객체 ID·원본 전체 해시·기존 앞부분의 바이트 일치를 보호된 핸들에서 확인한다. 현재 승인을 다시 확인해 이어쓰기 의도를 저장한 뒤 남은 부분만 복사하고, 전체 SHA-256과 기본 메타데이터를 검증·기록한다. 손상·교체·미기록 파일은 덮어쓰지 않는다. 원본 제거·최종 이름 확정·이동 완료 처리는 하지 않으며 원래 실패/취소 상태를 보존한다. 검증된 재개 복사본의 최종 이름 확정은 별도 유스케이스로 제공하며 화면 연결은 후속 작업이다.

재개 복사본 확정 백엔드는 원본·임시 객체·전체 내용·수정 시각과 현재 승인을 다시 확인하고, 확정 의도를 먼저 저장한 뒤 같은 보호 세션에서 최종 이름으로 변경한다. 기존 목적지 파일은 덮어쓰지 않고 원본은 유지한다. 최종 객체 증거가 기록된 경우에만 별도 원본 제거 마무리로 넘길 수 있다. 이름 변경 후 결과 저장이 끊기면 원본과 최종 파일을 보존하고 재실행을 거부한다. 그 경우는 별도 명시적 확정 기록 복구로 처리하며 추가 사고 상황 검증은 남아 있으며 지원 경계는 앱의 명시적 전체 재개 선택으로 연결했다.

확정 기록 복구 백엔드는 일반 복사 또는 이어쓰기 이후 실제 확정 의도가 저장된 시도만 처리한다. 온전한 원본·최종 객체 ID·전체 해시·기본 메타데이터와 임시 경로 부재를 읽기 전용 보호 세션에서 확인하고, 현재 승인과 예상 기록을 다시 대조해 최종 확정 증거·복구 감사를 원자적으로 저장한다. 파일 이동/삭제·메타데이터 수정을 하지 않으며 상위 단계/계획도 완료하지 않는다. 기록 복구 뒤 원본 제거는 별도 명시적 마무리로 요청한다. 두 파일 중 하나라도 없거나 교체·변경됐다면 복구하지 않는다. Schema v8·규칙 JSON v3·승인 계획 v2 형식은 유지한다.

중단 전송의 원본·임시 파일·최종 파일은 읽기 전용 복구 유스케이스로 대조할 수 있다. 전체 복구 화면은 작업별 개수와 파일 경로·상태·차단 이유를 표시하며 전송 기록이 있는 계획에는 구형 일반 이동 기록 정리를 적용하지 않는다. 복구 검사가 파일을 자동으로 이동/삭제하거나 전송 완료로 바꾸지는 않는다.

v3 분류 규칙은 **노드 하나에 조건 한 종류**를 둔다. 자식은 조건을 이어 붙이고, 형제는 배열 순서대로 검사해 첫 일치 가지를 선택한다. 선택한 가지에서 더 내려갈 수 없어도 이전 형제로 돌아가지는 않는다. 어느 가지도 최종 목적지에 도달하지 못하면 전체 예외가 없는 한 미분류로 남는다. 명시적 제외는 이동하지 않는 별도 결과다. 목적지는 정리 루트에 대한 상대 경로다.

- [AI에 전달할 영어 JSON 작성 규격](docs/ai-rule-authoring-v3.md) · [검증용 예제](resources/rules/ai-example.v3.json)

외부 JSON을 불러올 때는 앱에서 검증한다. AI가 만든 규칙도 바로 실제 파일에 적용하지 말고 편집기의 규칙 시험과 미리보기를 거친다.

## 변경하면 안 되는 안전 원칙

- 사용자의 명시적 승인 없이 파일을 이동하지 않는다. 감시 결과도 자동 실행하지 않는다.
- 영구 삭제·조용한 덮어쓰기·로그 없는 파일 작업을 허용하지 않고, 재분석 지점을 따라가지 않는다.
- 경로 범위·승인된 검사 정책·파일 상태·충돌 정책을 이동과 되돌리기 전 확인한다. 내용 해시 승인과 메타데이터 승인을 임의로 서로 대체하지 않는다.
- 상태가 불확실하면 추측해 복구하지 않고 `NeedsRecovery`로 남긴다.

상세한 변경 규칙과 테스트 기준은 [설계 문서](docs/architecture.md)와 [협업 안내](docs/contributing.md)에 있다.

## 현재 남은 부분

설정 화면의 일반 설정 저장, 앱 종료 중 알림, 여러 감시 폴더의 동시 관리, 오래된 해시 없는 복구 기록을 처리하는 수동 절차는 아직 구현되지 않았다. 캐릭터 및 최종 화면 디자인도 작업 대상이다. 기존 v2 규칙은 읽을 수 있으나 편집은 명시적 변환이 필요하다.
